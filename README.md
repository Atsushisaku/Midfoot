# Midfoot — 姿勢可視化（スクワット／デッドリフト）

しゃがみ方・引き方を、インストラクターがクライアントに説明するときに使うツール。

伝えたい核心はひとつ：

> **姿勢は体格（各セグメント長の比）の関数であり、技術の優劣ではない。**

「上体が起きたままできる人」と「傾けないとできない人」がいることを、その場で図で示せるようにする。

| | URL |
|---|---|
| **スクワット** | **https://atsushisaku.github.io/Midfoot/** |
| **デッドリフト** | **https://atsushisaku.github.io/Midfoot/deadlift.html** |

画面の左上のリンクで種目を行き来できる（言語もそのまま引き継ぐ）。

## 使う（スクワット）

タブレット横持ちを想定。キーボード入力は一切不要で、スライダーとボタンだけで操作する。

- **ハイバー／ローバー** — 押した瞬間に上体が傾く。最大の見せ場
- **靴（フラット／20mm／リフティングシューズ）** — 足首の可動域の天井が動く
- **体型プリセット** — 標準／大腿が長い／上体が長い／脛が長い
- **深さ** — 立位からボトムまで連続。バーが常に中足部の垂直線上を動くことが見える
- **足首の硬さ** — 上体角度に対する支配力が全入力中で最大
- **体格を固定** — 2体を並べて比較（「私はこう、あなたはこう」）

## 使う（デッドリフト）

模範フォームの開始姿勢と挙上を見せる。**動かせるのは体格とスタンスだけで、
腰の高さ・腕の角度・肩の位置はそこから決まる出力**になっているのが要点。

- **体型プリセット** — 標準／大腿が長い／体幹が長い
- **腕の長さ** — 短い／標準／長い。**背角はほとんど変わらず、腰の高さと引く距離が変わる**
  （「腕が長い＝背中が立つ」という誤解を正せる）
- **スタンス** — ナロー／ミドル／スモウ。詳細で開き角のスライダー
- **挙上** — 床からロックアウトまで連続。自動再生あり
- **比較** — 2体を並べて、体格の違いで腰の高さが変わることを示す

## 開発

```bash
npm install
npm run dev      # 開発サーバ
npm test         # ユニットテスト（幾何モデル）
npm run report   # 上体角度の一覧表を出力（数値調整用）
npm run build    # dist/index.html と dist/deadlift.html を単一ファイルで出力
```

成果物は **種目ごとに単一 HTML（各 約 30 KB）**。オフラインで動く（ジムの Wi-Fi 環境が悪い前提）。

`npm run build` が **2 回ビルドを走らせている**のは、単一ファイル化プラグイン
（`vite-plugin-singlefile`）が `inlineDynamicImports` を強制し、Rollup がそれを複数エントリと
併用できないため。2 回目は [`vite.deadlift.config.ts`](vite.deadlift.config.ts) が
`emptyOutDir: false` で `dist/` に追記する。

唯一の外部参照はアクセス計測（GoatCounter）の `<script>` 1 行で、これは `async` なので
**取得に失敗してもアプリは通常どおり動く**。Cookie も IP も保存しない。計測が不要なら
各 HTML の該当行を消せば、外部参照ゼロの単一 HTML に戻る。

`main` に push すると GitHub Actions がテストを通してから Pages に公開する。
**テストは両種目ぶんが同じゲートを通る**ので、デッドリフト側を壊すとスクワット版の公開も止まる。
電波が不安な現場で使うなら、公開ページをブラウザで保存するか `dist/` の 2 ファイルを
同じフォルダに置いておけば、ネットなしで同じもの（種目の行き来を含めて）が動く。

## 構成

| ファイル | 役割 |
|---|---|
| `src/geometry.ts` | 幾何モデルと解法。純関数のみ、DOM 非依存 |
| `src/geometry.test.ts` | ユニットテスト |
| `src/presets.ts` | 体型プリセットとスライダー範囲 |
| `src/render.ts` | SVG 描画 |
| `src/app.ts` | 状態・UI・補間アニメーション・URL 共有 |
| `src/deadlift/` | デッドリフト版一式（同じ構成。`../geometry` の定数とユーティリティ、`style.css` を共有する） |

`geometry.ts` を純関数に切り出してあるのが要点。つま先浮き・θ_t の範囲外・深さ補間の反転は
境界条件が多く、目視では回帰を検出できない。

## モデル

矢状面の 2D スティックフィギュア。未知数は脛・大腿・上体の3角度、制約は
「股関節が目標深さにある」「バー＝システム重心が中足部の真上にある」の2つ。
**3未知数・2制約なので1自由度残る**ので、そこに「足首の可動域を何割使うか」を入力として与える。

詳細と、実装中に判明してモデルを変更した経緯は [`docs/squat-visualizer-spec.md`](docs/squat-visualizer-spec.md) に全部書いてある。

デッドリフト版は拘束が違う。「バーが中足部の真上」＋「身体重心の位置」の 2 つだけで姿勢が閉じ、
**腕の角度も肩の位置も腰の高さも出力**になる（腕を鉛直と決め打つようなルールは使っていない）。
仕様は [`docs/deadlift-proto-spec.md`](docs/deadlift-proto-spec.md)、
何を入力にすべきかの事前検討は [`docs/deadlift-inputs-report.md`](docs/deadlift-inputs-report.md)。

## やらないこと

3D 表示、関節トルクの絶対値計算、動画解析、実測値（cm）の入力、スタンス幅・股関節外旋
（矢状面 2D では表現不可。注記のみで対応）。
