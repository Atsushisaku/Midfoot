## 1. 単位系・座標系（スクワット版と共通）

- 長さは無次元。**脛 + 大腿 + 体幹 = 1.0**（`src/geometry.ts` の `BASE_SEGMENTS {0.32, 0.31, 0.37}`
  と `normalize()` の考え方をそのまま使う。`mArm` は `foot` と同様、正規化に含めない）。
- 1 unit ≈ 身長の 0.779 倍。**cm 換算は H=170cm 固定で 1 unit = 132.4cm**
  （`CM_PER_UNIT = 132.4` を export。表示・report 用）。
- 座標: x 前方正・y 上方正、床 y=0、かかと x=0。足長 `FOOT = 0.2` 定数。
  足関節 = `(0.25·foot, 0.2·foot)` = (0.05, 0.04)、**中足部 midX = 0.5·foot = 0.1**。
- 角度の外部 IF は「度」。

## 2. 入力

```ts
interface DlBody {
  readonly mShank: number   // 0.8〜1.25、既定 1.0
  readonly mFemur: number
  readonly mTorso: number
  readonly mArm: number     // 腕（肩峰→グリップ）倍率。ARM_BASE = 0.488 unit に掛かる
  readonly foot: number     // 0.2 固定（プリセットは全て FOOT）
}

type BarSetting = 'standard' | 'block' | 'deficit' | 'small'
// バー中心の床からの高さ（unit）。補間アニメのため生値 {y} も受ける（BarSpec/ShoeSpec と同じ流儀）
type BarSettingSpec = BarSetting | { readonly y: number }
const BAR_SETTING_Y = { standard: 0.170, block: 0.208, deficit: 0.132, small: 0.113 }
// 由来: 22.5cm(20kgプレート半径) / 132.4、+5cm ブロック、−5cm デフィシット、r=15cm 小径

interface DlPoseInput {
  readonly body: DlBody
  readonly bar: BarSettingSpec
  /** スタンス開き角 α（度）0〜45。前額面の脚の開きを矢状面へ射影する見なしパラメータ */
  readonly stanceDeg: number
  /** 腰の高さ 0（低め）〜1（高め）。残り1自由度。既定 0.5 ≒ シャフトが脛に触れる位置 */
  readonly hipHeight: number
  /** 挙上進行度 0（床）〜1（ロックアウト） */
  readonly t: number
}
```

スタンスの簡易3択（presets.ts）: **ナロー α=0° / ミドル α=12° / スモウ α=35°**。
α=35 でナロー比 背角 +10.7°（調整目標 +10° に対して事前検算済み。文献のスモウ／
コンベンショナル体幹角差 5〜15° の範囲内）。

## 3. 解法（閉形式・純関数）

`solveDlPose(input: DlPoseInput): DlPose`。手順:

1. **正規化**: スクワット版 `normalize` と同じ（`BASE_SEGMENTS × 倍率 → 和で割る`）。
   `arm = 0.488 × mArm`（正規化外）。
2. **スタンス射影**: `femurEff = femur × cos α`、`shankEff = shank × cos(0.3α)`。
   体幹・腕は射影しない。
3. **バー**: `barY0 = resolve(bar)`、`barY_lock = K1.y + sqrt((femurEff+torso)² − (midX−ankle.x)²) − arm`
   ただし `K1 = (ankle.x, ankle.y + shankEff)`（脛鉛直・膝完全後退時の到達上限＝チェーンが
   一直線になる高さ。定義により t=1 は常に可解）。`barY(t) = lerp(barY0, barY_lock, t)`。
   バー x は常に `midX`（バー＝系重心の見なし。スクワット版 §4.6 と同じ近似）。
4. **肩ピン**: 腕は鉛直の張力部材と見なす → `S = (midX, barY + arm)`。
5. **膝（残り1自由度の閉じ方）**: 膝の足首からの前方量
   `kneeAhead0 = (midX − ankle.x) + kneeFwd`、`kneeFwd = lerp(0.045, 0.006, hipHeight)`
   （hipHeight=0.5 → kneeFwd=0.0255 ≒ シャフトが脛に触れる位置）。
   挙上中は「バーが膝を過ぎたら膝が後退する」を固定スケジュールで表す:
   `kneeAhead(t) = kneeAhead0 × (1 − smoothstep(0.25, 0.75, t))`（t≥0.75 で 0＝脛鉛直）。
   `K = (ankle.x + kneeAhead, ankle.y + sqrt(shankEff² − kneeAhead²))`。
6. **股関節**: 円 `(K, femurEff)` ∩ 円 `(S, torso)` の**後方解**（x が小さい方）。
   - `d = |S−K|` が `femurEff + torso` を超える（届かない）場合: 股関節を線分 K→S 上
     `K + femurEff·(S−K)/d` にクランプし `warn: 'reach'`。
   - `d < |femurEff − torso|`（退化）: 同様に半径比でクランプし `warn: 'reach'`。
   - `h² = femurEff² − a²` は `max(0, …)` で保護。
7. **角度**: `torsoDeg = atan2(S.x−hip.x, S.y−hip.y)/DEG`（**鉛直から**の前傾。スクワット版と
   同じ向きの規約）。表示・report 用に `backHorizDeg = 90 − torsoDeg`（水平から）も返す。

```ts
interface DlPose {
  readonly seg: Segments            // 既存の Segments を流用（foot 含む）
  readonly armLen: number
  readonly ankle: Vec; readonly knee: Vec; readonly hip: Vec
  readonly shoulder: Vec            // = 肩ピン（クランプ時のみ乖離しうる）
  readonly bar: Vec                 // (midX, barY(t))
  readonly heel: Vec; readonly ball: Vec; readonly toe: Vec; readonly mid: Vec
  readonly midX: number
  readonly torsoDeg: number         // 鉛直からの前傾（度）
  readonly backHorizDeg: number     // 水平からの背角（度）= 90 − torsoDeg
  readonly shinDeg: number          // 脛の前傾（度）
  readonly plateR: number           // = barY(t=0 の設定値でなく現在の描画用: プレート半径は設定値固定)
  readonly warn: 'none' | 'reach'
}
```

注: プレート円盤の半径は**セッティングの生値**（`resolve(bar)`）で固定。挙上中は円盤が
バーと一緒に床から浮く（`bar.y > plateR` になる）。

8. **クランプ**: `stanceDeg → [0,45]`、`hipHeight → [0,1]`、`t → [0,1]`、`foot ≥ 0.05`。
   すべての入力の直積で NaN を出さないこと。

## 4. 検算目標（実装の正しさの判定基準）

事前検算（この単位系・この定数・正規化込みの倍率入力で計算済み）と一致すること。許容 ±0.3°
（腰高は ±0.5cm）。すべて既定（標準体格・標準バー・α=0・hipHeight=0.5・t=0）からの単独変化:

| 条件 | backHorizDeg | 腰高(cm) |
|---|---|---|
| 基準（kneeFwd=0.0255） | **41.3°** | 54.8 |
| α=12°（ミドル） | 42.6° | 54.0 |
| α=35°（スモウ） | **52.0°** | 48.5 |
| mArm=1.18（腕長プリセット） | 46.1° | **63.5** |
| mFemur=1.18 | 33.0° | 61.9 |
| mTorso=1.18 | 49.7° | 45.8 |
| long-femur プリセット（mFemur 1.18, mTorso 0.92） | 27.9° | 66.5 |
| long-torso プリセット（0.96/0.94/1.18） | 52.6° | 42.7 |
| hipHeight=1（kneeFwd 0.006） | 37.4° | 57.4 |
| hipHeight=0（kneeFwd 0.045） | 45.2° | 52.4 |
| ブロック | 43.1° | 58.7 |
| デフィシット | 40.1° | 50.5 |
| 小径プレート | 39.8° | 48.2 |

向きの要点（テストの単調性検証に使う）:
- **スモウほど立つ**（α↑ → backHoriz↑）、**大腿が長いほど寝る**、体幹が長いほど立つ
- **腕の効きは腰高が支配的**: mArm ±0.05（腕 ±2.4cm）で背角は ±1.5° 未満、腰高は ±2cm 動く。
  プリセット幅（mArm 1.18）でも背角 +4.8° に対し腰高 +8.7cm ← 本アプリの見せ場
- hipHeight↑（腰高め）→ backHoriz↓（背中は寝る）
- t↑ でバー y は単調増加、t=1 で torsoDeg は小さい（< 20°）

## Rev.2（2026-07-31）— プロト初回レビューによる変更

atsushi さんの実機確認フィードバックによる改訂。以下は §2〜§8 に優先する。

1. **バーセッティングの UI を削除**。ソルバ API（`BarSettingSpec`）と既存テストは温存し、
   UI は常に `'standard'` を渡す（22.5cm 固定）。ブロック/デフィシット/小径のボタンは出さない。
2. **体型プリセットは 3 つ**: 標準／大腿が長い／体幹が長い（「腕が長い」を削除）。
   **腕は独立入力**にする: 簡易時は 3 択 `ARM_LEVELS`＝短い 0.90／標準 1.00／長い 1.10
   （スクワット版の足首 3 段階と同じ枠）、詳細時は mArm スライダー。プリセットは mArm を
   1.0 にリセットする（スクワット版プリセットが romDeg を含むのと同じ扱い）。
3. **描画: 腕と首の管を太く**。現行の本体幅 ×0.5（腕）/×0.62（首）は細すぎる。
   ×0.72（腕）/×0.75（首）を起点に目視調整。
4. **腕の見なしモード `armMode: 'vertical' | 'scapula'` を追加**（UI はトグル。既定 `vertical`）。
   よくある誤解「腕は必ず鉛直」に対し、実際の構えでは肩がバーより前に出て腕が傾くこと
   （とスモウでは鉛直に近づくこと）を見せるための機能。
   **因果関係の注意（2026-07-31、atsushi さん指摘）**: 力学的な必要条件は
   「合成重心（高重量ではほぼバー）が中足部の真上」だけであり、肩甲骨の位置や腕の傾きは
   本来**その結果として決まる出力側の変数**。「肩甲骨の下部がバー真上」は Rippetoe 系の
   経験則＝指標にすぎない。本モードはその指標を作図条件として課す**見なし**であって
   力学を解いたものではない（vertical の「腕＝鉛直の張力部材」も同じく見なし）。
   バー＝中足部真上という根本拘束は両モードで常に維持される。注記にも同旨を記載。
   - `scapula`: 肩関節から上体軸に沿って背中側へ `scapDrop` 下がった点がバー鉛直線上に来る。
     肩ピンが `S.x = midX + scapDrop·u.x`、`S.y = barY + √(arm² − (S.x−midX)²)`（u は上体
     単位ベクトル、股→肩）となり **u が解に依存する陰関数**なので不動点反復で解く
     （u.x=0 から開始、上限 40 回、収束判定 1e-12。現実グリッドでは 15〜18 回で機械精度）。
   - `scapDrop` は入力（0〜0.12 unit、**既定 0.08** ≒ 背面 11cm）。詳細スライダーで調整可能
     （効きが大きく体感調整が必要なため。指導者判断で確定するまでプロトでは可変にしておく）。
   - `barY_lock`（ロックアウト高）も同じ反復で解く（完全伸展 d = femurEff+torso を拘束に
     u を反復）。t=1 で warn が出ないこと。
   - 事前検算（標準体格・α=0・hipHeight=0.5・t=0）: scapDrop=0.08 で背角 41.3→**27.9°**、
     肩がバーの 9.4cm 前、腕の傾き 8.3°。scapDrop=0.06 → 31.6°/6.8cm/6.0°。
     α=35（スモウ）では腕の傾きが減る（鉛直に近づく）— これが見せたい現象。
   - `DlPose` に追加: `armDeg`（腕の鉛直からの傾き、度）、`scapula: Vec`（マーカー描画用。
     vertical モードでは肩と一致）。描画: scapula モード時のみ肩甲骨点に小さい印。
5. **テスト**: 鉛直モードの回帰値（§4）は不変のまま維持。scapula モードを追加:
   拘束残差（肩甲骨点の x − midX）< 1e-6・α↑で armDeg 減・mArm/スタンス/腰高グリッドで
   有限＆収束・t=1 で warn なし・scapDrop=0 が vertical と一致。

## Rev.3（2026-07-31）— 腕ルールの全廃と重心閉じへの移行

atsushi さんの指摘「本質は『バーがミッドフット上』＋『合成重心がミッドフット上』」を受けた
モデル改訂。**Rev.2-4 の armMode / scapDrop は全廃**（鉛直も肩甲骨基準も削除。誤りセッティングの
指摘は将来の別アプリで扱う）。

### 検討で判明したこと（経緯として重要）

合成重心はバー位置と身体重心の内分点なので、「バー x = midX」と「合成重心 x = midX」を
**両方等式で課すと重量比が消えて「身体単体の重心 x = midX」が強制される**。これを満たす
姿勢は標準体格で背角 10°・肩がバー前方 22cm と非現実的（数値検証済み）。現実には身体重心は
かかと〜足首上にあり、合成重心（COP）は「点」ではなく**支持基底（足）の中**にあればよい。
よって本質を守る正しい定式化は「バー x = midX」＋「**身体重心 x = 選べる位置（かかと〜中足部）**」
であり、腕の角度・肩の位置はそこから**出力として**決まる。旧2モードはこの閉じ方の端点として
再現される（かかと荷重 ≒ 腕鉛直、中足部荷重 ≒ 肩前方・腕傾き大）。

### モデル

- **入力の変更**: `armMode` / `scapDrop` を削除。`comPos: 0〜1` を追加（0=かかと、1=中足部。
  身体重心 x の目標 `comT = comPos × midX`。**既定 0.3**（comT=0.03 ≒ かかと前方 4cm。
  実測 COP（足長の35〜40%）と高重量の荷重比から逆算した現実的既定値））。
- **身体質量モデル**（Winter の標準値。矢状面射影に同じ質量を使う見なし）:
  質量比 = 足 0.029 / 下腿 0.093 / 大腿 0.20 / 体幹+頭 0.578 / 腕 0.10（計 1.0）。
  節内重心（近位から）= 下腿 0.433（膝から）/ 大腿 0.433（股から）/ 体幹+頭 0.60（股→肩軸上。
  頭部込みで体幹単体の 0.5 より遠位）/ 腕 0.43（肩→バー線上）/ 足 = 0.5·foot（床上）。
- **解法**: 膝は従来どおり閉じる。未知数は大腿角 φ と体幹角の 2、拘束は
  「|肩 − バー| = 腕長」（円交点で肩を消去）＋「身体重心 x = comT」の 2 で**自由度 0**。
  φ の物理枝（円が交わり、肩 y > 股 y、上側交点）で残差 comX(φ) − comT は単調減少なので、
  粗い走査（0〜140°、2° 刻み）で括って二分法 50 回。**目標が到達範囲外なら達成可能な
  端にクランプして warn 'reach'**（NaN を出さない）。
- **ロックアウト高**: 直立チェーン `ankle.y + shankEff + femurEff + torso − armLen`（反復不要）。
- **`DlPose`**: `scapula` を削除。`armDeg` は維持（完全に出力になる）。達成した重心 x を
  `comX` として追加（床マーカー描画用）。
- **腰の高さスライダーは維持**（膝の閉じ方は独立の自由度のまま）。

## Rev.5（2026-07-31）— 足首位置の解剖学的修正と hips-through ロックアウト

atsushi さんの指摘「フィニッシュでバーが身体から遠すぎる。かかとが長く、足首関節はほぼ
かかとにあるはず」への対応。検討の結果、指摘は 2 つの独立な問題に分解された:

1. **かかとの描画が長い（解剖学的事実）**: 足首関節は足長の約 20%（かかと後端から
   約 5cm）にある。現行の 0.25（6.6cm）は 1.5cm ほど前すぎる。
   → **DL ローカルの `ANKLE_X_RATIO` を 0.25 → 0.20**（スクワット版の定数は触らない）。
   開始姿勢への影響は +0.1° 程度で無視できる（検算済み）。
2. **バーが遠く見える本当の原因は「hips through」の欠落**: 旧モデルはトップでも
   (a) 膝を足首の真上（脛鉛直）に戻し (b) 身体重心目標をかかと寄り 0.03 のまま固定して
   いたため、腰がバーの 13cm 後方に残っていた。実際のロックアウトは**脚全体がわずかに
   前傾して骨盤がバーの下に入り、上体の軽い後傾でバランスする**。
   → 2 つのスケジュールを導入:
   - **膝の終端 `KNEE_AHEAD_TOP = 0.02`**: `kneeAhead(t) = kneeAhead0 + (0.02 −
     kneeAhead0)·smoothstep(0.25, 0.75, t)`（0 ではなく全脚のわずかな前傾へ）
   - **重心目標のスケジュール `COM_TOP = 0.06`**: `comT(t) = lerp(comPos·midX, 0.06, t)`
     （立位の自然な身体重心は足首とミッドフットの間 ≈0.06〜0.07 にあるため。
     `comPos` 入力は開始時の値という意味になる）
3. **解の枝の妥当性フィルタ**: pose 妥当性条件に **背角 ≦ 105°**（鉛直 +15° までの後傾）を
   追加する。φ の走査開始は **0° のまま**とする — hips through のロックアウト解は
   膝終端 `KNEE_AHEAD_TOP` が脚の前傾を担うため φ≈+2° に来る。実装検証で「−20° から
   走査すると非物理枝（上体の倒れ込み）を全域 4131 ケース中 4 件拾い、全部がグリッチ
   （トップ直前に背角 104° へ飛ぶ）」と判明したため、負側走査は採用しない（2026-07-31）。

## Rev.6（2026-07-31）— バー・クリアランス制約（脛・膝への食い込み解消）

atsushi さんの指摘「バーが膝と脛上部に食い込んで動作している」への対応。原因は膝後退が
t 駆動の決め打ちで、バーが脛上部〜膝を通過する時間帯（t≈0.3〜0.6）に膝がまだ前に
残っていたこと。**根本（幾何）で修正する**（描画の重ね順では「膝がバーの鉛直線を横切る」
不自然さが残るため）。

- **`BAR_CLEARANCE = 0.022`**（unit）: 脛の中心線とバー中心の最小水平距離
  （脛の描画半幅 ≈2cm ＋ バー軸の余白 ≈ 2.9cm 相当。標準体格の開始姿勢の自然値 0.0239
  よりわずかに小さく取り、標準の開始姿勢を変えない）。
- **膝前方量の上限（クリアランス・キャップ）**:
  `kneeY0 = ankle.y + √(shankEff² − min(kneeAhead0, 0.99·shankEff)²)`（開始閉じでの膝高の近似）、
  `ratio = clamp((barY − ankle.y)/(kneeY0 − ankle.y), 0, 1)`、
  `cap = ratio > 0 ? (midX − BAR_CLEARANCE − ankle.x)/ratio : ∞`。
  **`kneeAhead = min(base(t), cap, shankEff)`**（base は Rev.5 の t スケジュールのまま）。
  バーが脛を這い上がるにつれ膝が押し戻され、バーが膝より上に出た後は膝がバーの
  2.9cm 以上後ろに保たれる。
- 効果（検証済み）: 全域（プリセット×α×腕×t、567 ケース）で
  **バー→脚ラインの水平距離の最小値 = 2.91cm ちょうど**（食い込みゼロ）、解なし 0 件。
- 開始姿勢への影響: 標準・スモウ・大腿長などは不変。**体幹長プリセットのみ
  45.6→44.7°**（脛が相対的に短く急なため開始からキャップが効く ＝「シャフトが脛に
  触れる」閉じの厳密化であり意図どおり）。
- 挙上初期に背角が最大 0.93° 沈んで戻る（バーが脛を這う間は膝が先に伸びて背角ほぼ一定、
  という実際の引き出しに一致）。**単調性テストの許容は −0.5° → −1.0° に変更**（理由を
  コメントに書くこと）。
