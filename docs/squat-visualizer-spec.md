# スクワット姿勢可視化アプリ 要件仕様

> Rev.2（2026-07-27）。初版からの変更点は末尾 §14 にまとめてある。

## 1. 目的

スクワットのしゃがみ方を **インストラクターがクライアントに説明するとき** に使うツール。

伝えたい核心はひとつ：

> **上体の傾き量は体格（各セグメント長の比）と担ぎ位置の関数であり、技術の優劣ではない。**

「上体が起きたままできる人」と「傾けないとできない人」がいることを、その場で図で示せるようにする。

## 2. 想定ユーザーと使用状況

- パーソナルトレーナー／指導者
- クライアントの目の前で、タブレット横持ち（またはPC）で見せながら説明
- 説明中の操作時間は数秒。**キーボード入力は一切させない**（スライダーとボタンのみ）
- 精度より操作速度と一目での分かりやすさを優先

## 3. スコープ

### やること
- 矢状面（横から見た）2Dスティックフィギュアの静的／準静的な姿勢表示
- ハイバー／ローバーの切り替えによる上体角度の変化
- 体格比の変更による上体角度の変化
- 足首の背屈可動域による「出せる脛角度の上限」の表示
- 2体の比較表示

### やらないこと（明示的に除外）
- 3D表示
- 関節トルクの絶対値計算、筋活動の推定
- 動画解析・実写トレース
- 実測値（cm）の入力と計測方法ガイド
- スタンス幅・股関節外旋（矢状面2Dでは表現不可。注記のみで対応）
- 体幹の剛性・腹圧・肋骨位置（別テーマ）

## 4. 物理モデル

### 4.0 単位系

**全長を無次元で扱う。** 総長 `L_shank + L_femur + L_torso = 1.0` を常に満たす（§4.8）。
以下に出る長さはすべてこの単位。cm 等の実寸には一切変換しない。

### 4.1 座標系

- 床を `y = 0`、前方（つま先方向）を `+x`
- かかと `x_heel = 0`、つま先 `x_toe = L_foot`
- **中足部** `x_mid = 0.5 * L_foot`（バーの垂直基準線）
- 足関節 `A = (0.25 * L_foot, 0.20 * L_foot)`

### 4.2 セグメントと角度

| 記号 | 意味 |
|---|---|
| `L_shank` | 脛長（足関節→膝） |
| `L_femur` | 大腿長（膝→股関節） |
| `L_torso` | 上体長（股関節→肩） |
| `L_foot` | 足長 |
| `θ_s` | 脛の前傾角（鉛直基準、膝が前に出る方向を +） |
| `θ_f` | 大腿の角度（水平基準、股関節が膝より高い方向を +） |
| `θ_t` | 上体の前傾角（鉛直基準、前傾を +） |

```
K (膝)     = A + L_shank * ( sin θ_s, cos θ_s )
H (股関節)  = K + L_femur * ( -cos θ_f, sin θ_f )
S (肩)     = H + L_torso * ( sin θ_t, cos θ_t )
```

### 4.3 バー位置のモデル化

上体の単位ベクトル `u = (sin θ_t, cos θ_t)`、その後方法線 `n = (-cos θ_t, sin θ_t)` として：

```
B (バー) = H + r * L_torso * u + d * n
```

| 担ぎ位置 | `r`（上体長比） | `d`（後方オフセット） |
|---|---|---|
| ハイバー（僧帽筋上部） | 1.00 | `0.03 * L_torso` |
| ローバー（肩甲棘上） | 0.87 | `0.08 * L_torso` |

> **重要**：ローバーは上体軸の延長線上ではなく **上体の後方** にある。`d_low > d_high` は必須。
>
> この値で標準体型・θ_s=30°・最深時にハイ 34.4° / ロー 43.4°（差 9.0°）となる。現実的な範囲なので **既定値として採用する**。

### 4.4 靴のヒール高 ★仕様変更（初版から意味が変わった）

**ヒール高は図の幾何に反映しない。** 足関節 `A` も中足部基準線 `x_mid` も靴によって動かない。
ヒール高が効くのは **「出せる脛角度の上限」だけ** である（§4.5）。

ただし **描画上は靴底を描き、かかとが実際に持ち上がる**（Rev.5）。骨格の解には一切影響しない
表示だけの処理で、靴の選択が図の上で分かるようにするためのもの（§7）。

足部がヒール高 `h` で前傾する角度を `φ` とする。回転の支点はつま先ではなく **中足骨頭（かかとから足長の約 70%）** なので：

```
φ = asin( h / (k_pivot * L_foot) )      k_pivot = 0.70
```

| ボタン | `h`（無次元・総長基準） | 標準足長（0.20）での `φ` |
|---|---|---|
| フラット（0mm） | 0 | 0.00° |
| ランニングシューズ相当（20mm） | 0.0147 | 6.03° |
| リフティングシューズ（〜25mm） | 0.0183 | 7.51° |

> `h` を「足長比」ではなく**総長基準の絶対値**で持つこと。足長比で持つと足の大きさに関わらず `φ` が一定になり、「足が大きい人ほど同じヒールでは効きが小さい」という現実が消える。

### 4.5 制約条件と自由度

未知数は `θ_s, θ_f, θ_t` の3つ。制約は2つ：

1. **深さ条件**：`H_y = target_hip_y`（§4.7）
2. **バランス条件**：`B_x = x_mid`（バー＝システム重心が中足部の真上）

**3未知数・2制約なので1自由度残る。** この残る自由度が `θ_s`（膝をどれだけ前に出すか）であり、ユーザー入力で与えることで解が一意に決まる。

> この点を押さえずに実装すると必ず詰まるので注意。

#### 脛前傾角の与え方 ★Rev.3 で変更

`θ_s` は **度数ではなく「足首の可動域を何割使うか」** で与える：

```
θ_s_max = ROM + φ                    ( この体格・この靴で出せる上限 )
θ_s     = usage * θ_s_max            ( usage ∈ [0, 1] )
```

- `ROM` は「足首の硬さ」スライダー（体格パラメータの一部）
- `usage` は「膝の前送り」スライダー。既定 100%、下限 30%
- **上限を超える状態が原理的に作れない。** クランプも、それに伴う「背屈が上限」の警告も不要になった
- **どの `usage` でも靴ボタンが図を動かす。** `φ` が増えれば `θ_s_max` が増え、比例して `θ_s` も増える

> **なぜ度数入力をやめたか**
>
> 初版〜Rev.2 は「背屈」スライダーで `θ_s` を度数指定し、`ROM + φ` でクランプしていた。問題は2つ：
>
> 1. **「背屈」と「足首の硬さ」が隣り合った度数入力で、区別がつかない。** 前者は使い方の選択、
>    後者は変えられない容量なのに、どちらも足首の話に聞こえる。クライアントの前で
>    「背屈を上げます、でも足首の硬さは変えません」と言った瞬間に破綻する。
> 2. **可動域を使い切っていないと靴ボタンが図を一切動かさない。** クランプしていないので当然だが、
>    押しても何も起きないボタンとして体験される。
>
> 比率で持つとどちらも消える。現場の語彙とも一致する（脛の角度を度数で意識する人はいない）。
>
> なお **自由度そのものは残した。** `θ_s = ROM + φ`（常に使い切る）に固定するとモデルが嘘をつく。
> ローバーの選手は意図的に足首を使い切らずに後ろに座るので、それを表現できなくなる。

#### 各入力の支配力（標準体型・ローバー・ボトム）

| 入力 | 上体角度の範囲 | 幅 |
|---|---|---|
| 足首の硬さ 10〜45° | 29.6° 〜 75.5° | **45.8°** |
| 体型プリセット5種 | 35.0° 〜 65.0° | 30.0° |
| 膝の前送り 30〜100% | 34.4° 〜 58.5° | 24.1° |
| 担ぎ位置 ハイ／ロー | 34.4° 〜 43.4° | 9.0° |

最も効くのが **足首の硬さ**（解剖学的パラメータ）であることは、このアプリの主張を補強する。
使い方の選択（膝の前送り）の支配力は体型プリセットより小さい。

### 4.6 解法（閉形式）

`θ_s` が確定したとき：

1. `K` を計算
2. 深さ条件から `θ_f`（§4.7。スライダーの `p` が直接与える）
3. `H` を計算
4. バランス条件は `a·sin θ_t - b·cos θ_t = c` の形になる
   - `a = r * L_torso`, `b = d`, `c = x_mid - H_x`
   - `R = sqrt(a² + b²)`, `ψ = atan2(b, a)`
   - `θ_t = ψ + asin(c / R)`

θ_t の解が存在しない／範囲外になる場合は §5。

### 4.7 深さの定義 ★Rev.2 実装時に補間式を変更

深さスライダーは進行度 `p ∈ [0, 1]` を与える（0 = 立位、1 = ボトム、既定は 1.0）。

```
θ_s(p) = θ_s * sin( 90° * p )              ( θ_s = usage × (ROM + φ)、§4.5 )
θ_f(p) = 90° + p * ( θ_f_bottom - 90° )
θ_f_bottom = asin( r_knee_ratio - d_deep_ratio ) = asin( -0.04 ) = -2.29°
```

- `r_knee = 0.06 * L_femur`（膝の描画半径相当）
- `d_deep = 0.10 * L_femur`（IPF 合格ラインをどれだけ越えるか。固定）
- `θ_f_bottom` は `L_femur` に依存せず定数になる

`p = 0` で `θ_s = 0`・`θ_f = 90°`（脛も大腿も垂直）、`p = 1` で股関節が
`K_y + r_knee - d_deep`（IPF ラインの `d_deep` 下）に来る。**端点は初版と同一。**

深さの基準線（`y = K_y + r_knee`）は水平の破線として常時表示する。
各フレームの `K_y` で再計算するので、脛角度を変えると破線も動く。**ラベルは付けない**（§7.3）。

> 判定内容は「股関節の折れ目が膝上端より低い」。図の上に書くなら「股関節＜膝」だが、
> Rev.6 でラベル自体を廃止した。なお「パラレル」は現場で最も通じる語だが、
> パラレル＝大腿が床と平行であり、この線はそれより深いので不正確になる。

> **なぜ股関節「高さ」の線形補間をやめたか**
>
> 初版は `target_hip_y` を `p` に対して線形補間していたが、これだとしゃがみアニメーションの
> 終盤で **上体が最大 8° 起き上がる**（脛が長い体格ほど顕著）。
>
> バランス条件に効くのは
> `c = 0.25·L_foot − L_shank·sin θ_s + L_femur·cos θ_f`
> であり、高さを線形に動かすと `θ_f = asin(...)` が立位付近で一気に動いて早々に飽和する。
> その後は脛の前傾だけが進んで股関節を前に押し戻すため `c` が減少に転じる。
>
> `θ_f` を線形に振れば `dc/dp` はほぼ全域で正になり、反転は最後の数%で 0.5° 未満に収まる
> （大腿が水平を過ぎて股関節が膝の下に潜り込む分。幾何的に避けられない）。
> 股関節の角速度が一定になるので、動きとしても実際のしゃがみに近い。
>
> `θ_f` を指定することは（`K` が決まっていれば）股関節高さを指定することと1対1に対応するので、
> §4.5 の「3未知数・2制約」の構造は変わらない。スライダーの目盛りの取り方を変えただけである。

> この定義では深さ条件が常に解を持つため、**「深さに届かない」ケースは構造的に発生しない**（初版 §5 の1行目は削除した）。どの体格でも必ず合格ラインを `d_deep` だけ越えられる。

### 4.8 体格パラメータと正規化

セグメント長は「標準からの倍率」で持ち、描画前に総長 1.0 へ正規化する。

```
基準値  b = ( b_shank, b_femur, b_torso ) = ( 0.32, 0.31, 0.37 )
倍率    m = ( m_shank, m_femur, m_torso )   各 0.80 〜 1.25
L_i = b_i * m_i / Σ( b_j * m_j )
```

スライダーは3本とも独立に触れる（ツマミは触ったものだけ動く）が、正規化により1本上げると他の2つが相対的に縮む。

`L_foot` は正規化に含めない独立パラメータ（総長比）。**定数 0.20 に固定**しており、
スライダーにもプリセットにも出さない（理由は §13.2）。

### 4.9 立位ゴースト

立位ゴーストも §4.6 で解く（`p = 0` を代入するだけ）。`θ_s = 0` のとき `H_x = A_x` なので
`c = x_mid - A_x = 0.25 * L_foot ≈ 0.05`、標準体型で `θ_t ≈ 9°` の軽い前傾になる。

真っ直ぐ立たせる特例は設けない。バーが基準線から外れて描かれる方が説明上まずいため。

## 5. 解が存在しない場合の挙動 ★重要

エラーダイアログを出さないこと。**これ自体が説明のための最重要コンテンツ**である。

`θ_t` の許容範囲を `[θ_t_min, θ_t_max] = [-10°, 90°]` とする。`ψ` は小さい（2〜6°）ので
`f(θ_t) = a·sin θ_t - b·cos θ_t` はこの範囲で単調増加であり、上限は `f(90°) = a`。

| 条件 | 意味 | 表示 |
|---|---|---|
| `c > a` | バーが中足部より**後方**にしか置けない → 後ろに倒れる | **つま先が浮く**姿勢として描画（足部をかかと支点に回転） |
| `θ_t > 70°` | 現実的でない前傾 | 描画はするが注意表示 |

足部の回転角は `min( 15°, 60° * (c - a) / L_foot )` とし、超過量に応じて連続的に変える。
`θ_t` は許容範囲に丸めた値で描画する。足部は `かかと → 中足骨頭 → つま先` の折れ線。

> **つま先浮きは到達可能。** 足首が硬く（ROM 12° 等）膝の前送りを絞ると、股関節が後ろに残って
> `c > a` となり、後方に倒れる姿勢として描かれる。現場で実際に起きる失敗そのものである。

> **「背屈が足りない」は独立した状態としては存在しない**（Rev.3）。`θ_s` を可動域の比率で持つので
> 可動域を超えることがない。可動域が足りない人は脛が立ったまま股関節が後ろに残り、
> **つま先が浮く**として図に出る。テキスト警告より姿勢そのもので見せる方がよい。

### 5.1 かかと浮きは扱わない（Rev.4 で削除）

初版〜Rev.3 は `c < f(θ_t_min)`（バーが中足部より前方にしか置けない）を「かかとが浮く」として
描いていたが、**バーベルスクワットでかかとが浮くことはほぼない**（指導者の判断、2026-07）ため削除した。

モデル上も到達不能だった。股関節は必ず膝より `L_femur·cos θ_f` だけ後ろにあり、膝は足関節より
最大 `L_shank·sin θ_s` しか前に出ない。`θ_s ≤ ROM + φ` で頭打ちになるので `c` が負側の限界を割らない。
現実のかかと浮きは「足首が足りないのにさらに膝を前に出そうとする」ことで起きるが、
このモデルはその経路を構造的に塞いでいる。

その方向に振り切れる極端な体格（脛が極端に長く、大腿と足が極端に短い）を入力した場合は、
姿勢としては描かず `θ_t` を `θ_t_min` に丸めるだけにする（NaN 防止）。

> **初版の誤り（記録）**：初版は `c < -R` を「バーが後ろ」、`c > R` を「バーが前」としていたが、
> `c = x_mid - H_x` の定義から**逆**だった。また判定基準を `R` にしていたが、`θ_t` が全周動ける
> 前提の値なので実際には使えない。Rev.2 で `a` と `f(θ_t_min)` に修正し、Rev.4 で `a` のみになった。

## 6. 画面構成

```
┌──────────────────────────────────────────────┐
│                                              │
│         図（画面の約70%）                      │
│    ・立位ゴースト（薄いグレー）                 │
│    ・ボトム姿勢（実線）                        │
│    ・中足部から伸びる垂直線 1本                 │
│    ・IPF深さ判定の水平破線                     │
│                                              │
│             上体角度  42°                     │  ← 数値表示はこれ1つだけ
├──────────────────────────────────────────────┤
│ [ ハイバー | ローバー ]  [体型プリセット ▼]      │
│ [ フラット | 20mm | LS ]                      │
│ 深さ ──●──        足首の硬さ ──●──            │
│ ▼ 体格を調整                                  │
│   （折りたたみ：大腿・上体・脛・膝の前送り）      │
│ [ 体格を固定 ]                                │
└──────────────────────────────────────────────┘
```

スライダーは計6本だが、**常時見えるのは2本**（深さ／足首の硬さ）。

- **足首の硬さを常時側に置く理由**：上体角度に対する支配力が全入力中で最大（45.8°）であり、
  かつ靴ボタンとセットで説明する対象だから
- **膝の前送りを折りたたみに入れる理由**：使い方の選択であって体格ではないが、既定 100% で
  普段は触らない。「後ろに座る」話をするときだけ開く

セグメント長の3本もプリセットで足りるので折りたたみ。§2 の「数秒で操作」を優先した。

### 表示ルール
- 数値表示は **上体角度ひとつだけ** を大きく（比較モードのみ2つ）
- 良し悪しを示唆する色分け（赤＝悪い等）を **使わない**。「傾く＝悪いフォーム」と読ませないことがこのアプリの存在意義
- 中足部の垂直線は常に画面上の同じ位置に固定する。総長が常に 1.0 なので、体格を変えても図のスケールは変わらない
- 2体の色は **スカイブルー #3b9de8（体A＝操作中）／コーラル #ff8a66（体B＝固定）**（Rev.8）。
  青×橙は色覚多様性で最も区別しやすい組で、どちらも合否を連想させない。
  UI のアクセント色は体A に連動する
- 警告表示（つま先浮き・θ_t > 70°）は **バイオレット #7c3aed** 1色＋テキストのみ。
  コーラル（体B）と混同しないための選択で、姿勢そのものには着色しない

## 7. スティックフィギュアの描画仕様

純粋な棒だけでは、解剖を知らないクライアントが股関節の位置を認識できない。以下は必須：

- **関節に丸ポチ**：足関節・膝・股関節・肩
- **足部**：線1本ではなく、足裏の線＋つま先。**中足部に印**を付ける
- **頭**：丸
- **バー**：円で表現（背中側にあることが分かる位置）

筋肉・輪郭・服などは一切不要。

### 7.1 首・鼻・靴底（Rev.5 で追加）

**首**：肩から頭までを線でつなぐ。頭と首の寸法は実測の人体比に合わせる
（肩峰から頭頂まで総長比 0.234、頭の半径 0.083）。

> 初版はこれを 0.148 / 0.062 で描いていた。つまり **首が存在せず頭が肩に直接乗っていた**ため、
> 肩の高さにあるハイバーが「頭のすぐ下＝高すぎる位置」に見えていた。
> バーの `r`（ハイ = 1.00 = 肩峰）は解剖学的に正しい値なので、直すべきは頭の側だった。
> 実際、ハイバーは僧帽筋上部の上に乗るので `r` はむしろ 1.0 より大きいのが正確であり、
> ローバーの肩甲棘は肩峰の 4〜6cm 下なので `r ≈ 0.90`、現状の 0.87 は既にやや低い。

**鼻**：頭の円周上の弦を底辺とし、**頂点だけが外へ出る白抜きの小三角**（Rev.8 で作り直し。
色ベタ塗りの三角を輪郭の内側から生やすと、くちばしに見える）。
上体の傾きへの追従は 0.45 倍に減衰させる。剛体（1.0）だと深いボトムで鼻が真下を向いて
壊れて見えるし、実際の選手も上体ほどは頭を倒さない（前方の一点を見る）。

**ヒール**：`かかと(床) → 中足骨頭(床) → かかと(高さ h)` の直角三角形のくさび。
**フラットでは何も描かない**（h = 0）。`h` は §4.4 の実寸（20mm / 25mm）なので誇張しない。
足部は `かかと(高さ h) → 中足骨頭 → つま先` の折れ線となり、その傾きは
`atan(h / (k_pivot·L_foot))` で **φ と厳密に一致する**。

靴の甲（アッパー）は描かない。ソールは答えを変える機能部品なので §7 の「服は不要」には
抵触しないが、アッパーは情報を持たない装飾になる。

立位ゴーストには足部を描かない（実線の足部と完全に重なるだけなので）。

### 7.2 デッサン人形式（Rev.7。指導者のスケッチ [`figure-sketch.jpg`](figure-sketch.jpg) に合わせて全面変更）

Rev.6 の「関節の丸ポチを管の中に描く」方式は不評だったため、木製デッサン人形の様式へ：

- **関節（足首・膝・股関節）は独立した白抜きの円**。塗りは白、輪郭は体の色
- **セグメントは関節円を貫通せず、円の縁から縁まで** を白抜きの管として引く
- 上体は肩で止めず **股関節の円の縁から頭の円の縁まで1本**。肩の位置はバーの円が示すので
  肩の関節円は置かない（スケッチにも無い）
- 足の線は描かない。**靴のシルエットそのもの** を描く：
  `かかと(床) → つま先(床) → つま先上面 → 甲（足関節の下） → かかと上端(SHOE_COLLAR + h)`
  の閉じた多角形。足関節の円は靴の履き口に乗る
- ヒール `h` は **靴の中に色付きのくさび（直角三角形）** として描く。フラット（h=0）では消える。
  くさびの斜辺の傾きは `atan(h / (k_pivot·L_foot)) = φ` でモデルと厳密に一致する
- 中足部の印は靴底の小さな点に縮小
- バーの輪郭は管の壁と同じ太さで固定（四肢の太さに連動させると円を塗り潰す）

立位ゴーストは従来どおり簡素な線画（管にしない）。主図との対比で「参照」だと分かる。

### 7.3 ラベルを置かないもの（Rev.6）

中足部の垂直線と深さの基準線には **テキストラベルを付けない**。
足部の印と垂直線が重なっていること、破線が股関節のすぐ上にあることで意味は伝わり、
図の上の文字は少ないほどよい（§6：数値表示は上体角度ひとつだけ）。

## 8. インタラクション

### 8.1 ハイ／ローの切り替え ★最大の見せ場
トグルを押した瞬間に、上体が **0.3秒程度の補間アニメーション** で傾く。静止図を2枚並べるより圧倒的に伝わるため、ここに最も工数をかける価値がある。

### 8.2 しゃがみ動作のアニメーション
深さスライダーをドラッグすると立位↔ボトムが連続的に動く（§4.7 の `p`）。
- 各フレームで §4.6 を再計算
- バーが常に垂直線上を動くことが視覚的に分かるよう、バーの軌跡を薄く残す

### 8.3 靴の切り替え
靴を変えると `φ` が変わって `θ_s_max = ROM + φ` が動き、`θ_s = usage × θ_s_max` も比例して動く。
**膝の前送りが何%であっても図が変化する**（Rev.3 で変わった点。度数入力＋クランプだった頃は
可動域を使い切っているときしか動かなかった）。
ハイ／ローと同じく 0.3 秒の補間アニメーションを掛ける。

### 8.4 体型プリセット

### 8.5 比較モード ★MVPに含める

**スナップショット方式**：

1. スライダーで体Aを作る
2. `[ 体格を固定 ]` を押す → 体Aの **体格パラメータ5つだけ** が凍結され、薄い色で残る
3. スライダーで体Bに変える → 差が見える
4. `[ 固定を解除 ]` で単体表示に戻る

凍結されるのは体格のみ。**深さ・背屈・ハイ／ロー・靴は共有のまま両方に効く**。
「同じ条件で体格だけが違う二人」という統制された比較にするための設計であり、
「私はローバー、あなたはハイバー」のような担ぎ位置違いの比較はできない（意図的な制限）。

レイアウトは `[ 重ねる | 並べる ]` トグルで切替：

| | 中足部の垂直線 | IPF 破線 |
|---|---|---|
| 重ねる | 共有1本 | 2本（各体の色。脛長が違えば高さがずれる） |
| 並べる | 各体に1本 | 各体に1本 |

**既定は「並べる」**（§13.1）。

深さスライダーは1本を共有する。ボトムの股関節高さは各体の `K_y` から個別に計算されるので、
両方が「自分の合格ライン − 同じ量」の位置に来る。これがルール上フェアな比較になる。

上体角度は2体ぶん表示する。

## 9. 注記として画面に載せるテキスト

- 「バーではなく、身体＋バーの合成重心が中足部の上にあるのが正確な条件。高重量ではバー位置で近似できる」
- 「上体は1本の棒として扱っている（実際は腰椎・胸椎で角度が分散する）」
- 「スタンス幅を広げたり股関節を外旋させると、矢状面では大腿骨が短くなったのと同じ効果が出る。この図では表現していないが、実際の解決策としては有効」
- 「靴のヒールは最適な傾き量を変えるのではなく、その脛角度に**届くかどうか**を変える」
- 「ローバーは前傾を**減らすのではなく増やす**。ローバーが買っているのは『脛を立てたままバランスが取れること』で、対価が前傾と股関節・背部の負担。大腿が長い人ほどこの増分は大きい」
- 「身長そのものは上体角度に影響しない。効くのは**セグメントの比率だけ**で、比率が同じなら大柄でも小柄でも答えは変わらない」
- 「傾きの大きさは体格による最適解であり、フォームの優劣ではない」

> **補足（この注記を足した理由）**
>
> 「大腿が長い人は前傾を抑えるためにローバーを選ぶ」という誤解が実際に出た。モデルは逆を示す：
>
> | 大腿倍率 | ハイバー | ローバー | 差 |
> |---|---|---|---|
> | 1.00 | 34.4° | 43.4° | +9.0° |
> | 1.18 | 46.0° | 58.3° | +12.3° |
> | 1.30 | 55.2° | 72.1° | +17.0° |
>
> 大腿が長いほど増分が大きくなる。担ぎ位置そのものは**バー荷重の関節モーメントアームを変えない**
> （バーは常に中足部の真上なので、股関節・膝のモーメントアームは骨格配置だけで決まり、`r` と `d` に依存しない）。
> ローバーが変えるのは「その骨格配置でバランスを取るのに必要な上体角度」だけである。
>
> 誤解の出どころはおそらくワイドスタンスとの混同。ローバーはワイドスタンス＋股関節外旋とセットで
> 使われることが多く、これは矢状面では大腿が短くなったのと同じ効果を持つ（効き幅 30° 以上）。
> ただし「ハイバー・ナロー 46.0° → ローバー・ワイド 47.6°」はほぼ引き分けで、減りはしない。


| コマンド | 内容 |
|---|---|
| `npm run dev` | 開発サーバ |
| `npm test` | ユニットテスト |
| `npm run report` | 上体角度の一覧表を出力（数値調整用） |
| `npm run build` | `tsc --noEmit` 後に `dist/index.html` を1ファイル出力 |

成果物は **`dist/index.html` 単一ファイル 19.6 KB**（gzip 8.4 KB）、外部依存なし。

### 13.2 決着した項目（Rev.4・モデル判断）

**足長 `L_foot` → 定数 0.20 に固定、「小柄」プリセット削除。**
効果は当初「約 1.4°」と記録していたが**これは誤り**で、0.03 ぶんの変化を全範囲と取り違えていた。
正しくは 0.16〜0.24 の全範囲で 3.6°（ハイ）/ 4.5°（ロー）あり、担ぎ位置（9.0°）の半分に相当する。

| 足長 | ハイバー | ローバー |
|---|---|---|
| 0.16 | 32.6° | 41.2° |
| 0.20 | 34.4° | 43.4° |
| 0.24 | 36.2° | 45.7° |

削除の理由は効果が小さいからではなく、**この効果がモデルの規約の産物であって物理的予測ではない**から。
モデルは「バーは必ず中足部の真上」と決め打ちしているので、足が大きいほど中足部が足関節より前に出て
前傾が増える。しかし現実の制約は「重心が支持基底の中にあること」であり、足が大きければ基底も広がって
自由度が増す。モデルはこの自由度を表現できず、拘束だけが残って根拠のない向きの予測を出していた。

代替案（中足部の線を帯にして許容幅を可視化）を採らなかったのは、帯を描いても解いた姿勢は帯を使わない
（バーは中足部にピン留めのまま）ため飾りにしかならないから。実質化するには「傾きを X° 減らしたら
バーはここに来る＝まだ基底内」という別機能が要り、§3 のスコープを超える。

代わりに §9 へ **「身長そのものは上体角度に影響しない。効くのはセグメントの比率だけ」** を追加した。
総長を 1.0 に固定している以上これはモデルの厳密な帰結であり、「小柄だから」という現場でよく出る説明を
否定できる、教えるに値する事実である。

**立位ゴーストの前傾 → 変更せず。**
Rev.2 の記録「8.5〜10.7°」はハイバーの値で、ローバーでは 13.1〜15.5°（標準 14.2°）になる。
そして **§13 に書いていた対処法（`x_ankle` の係数 0.25 → 0.30）は効かない**：

| | 立位（ロー） | ボトム（ハイ） | ボトム（ロー） |
|---|---|---|---|
| 現状 | 14.2° | 34.4° | 43.4° |
| 係数 0.30 相当 | 12.7° | 32.9° | 41.6° |

立位で 1.5° 減る代わりにボトムでも 1.5〜1.8° 減る。全体が平行移動するだけで立位だけは起こせない。

原因は、ローバー立位の 14.2° のうち **5.25° が `ψ = atan2(d, a)` の項**だから。
「バーが上体軸より後方 `d` にあるので、バーを股関節の真上に持ってくるだけで上体を `ψ` 倒す必要がある」
ぶんであり、減らすには `d` を小さくするしかない。それはハイ／ローの区別そのものを潰す。
14° は物理的に正しく（ローバーを担いで立てば実際わずかに前傾する）、実機では直立として読めたので閉じた。

**比較モードの既定レイアウト → 「並べる」。**
「重ねる」では2体の脛と足がほぼ完全に重なる（比較で変えるのは主に大腿・上体で、脛は近い値のまま、
足長は共通）ため、後ろの体は上体と頭しか見えない。「並べる」は各体に中足部線と IPF 線が付いて即座に読める。
「重ねる」はトグルで残す：差の所在を1枚で示せる固有の価値があるので、話が通じた後の決め手に使う。

1. **深さの補間を「股関節高さ線形」から「大腿角 θ_f 線形」へ変更**（§4.7）。
   高さ線形だとしゃがみアニメーションの終盤で上体が最大 8° 起き上がる。端点は不変。
2. **かかと浮きの描画を「足部全体の回転」から「中足骨頭より後ろだけを持ち上げる」へ変更**（§5）。
   全体を回すとつま先が床下に潜る。→ Rev.4 でかかと浮きごと削除（§5.1）。
3. **靴の `φ` の数値を訂正**：ランニング 6.2° → 6.03°、リフティング 7.7° → 7.51°（§4.4）。
   Rev.2 執筆時の計算違い。式は変えていない。
4. **かかと浮きの分岐がスライダー範囲では到達不能と判明** → Rev.4 で削除（§5.1）。

## 16. Rev.3：脛前傾角の入力を度数から比率へ

「背屈角の入力があるべきなのか。実際、意識することはほぼない」という指摘を受けての変更。

| | Rev.2 | Rev.3 |
|---|---|---|
| 入力 | 「背屈」＝ `θ_s` を度数指定 | 「膝の前送り」＝ 可動域の使用率 0〜1 |
| 上限処理 | `min(θ_s_req, ROM + φ)` でクランプ | クランプ不要（原理的に超えない） |
| 警告 | 「背屈がここで上限」を表示 | 廃止。可動域不足はつま先浮きとして図に出る |
| 靴の効き | クランプ中のみ図が動く | 常に図が動く |
| 常時表示スライダー | 背屈／深さ／足首の硬さ（3本） | 深さ／足首の硬さ（2本） |
| 膝の前送り | — | 折りたたみ内、既定 100% |

API の変更は `PoseInput.shankReqDeg` → `shankUsage`、`Pose.dorsiflexionClamped` 削除、
`Pose.shankUsage` 追加のみ。§4.6 の解法本体には手を入れていない。

**採らなかった案**：膝の前送りを担ぎ位置トグルに連動させる（ハイバー 100%／ローバー 75%）。
実際の使われ方には近いが、75% という数字に根拠がなく、かつ §4.3 の「ローバーは +9°」という
主張が「+18°」に化けて2つの機構が混ざる。トグルは `r`, `d` だけを動かす純粋な状態に保つ。
